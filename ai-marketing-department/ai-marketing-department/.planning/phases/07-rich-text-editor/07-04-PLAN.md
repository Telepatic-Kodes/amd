       ```typescript
       editorProps: {
         attributes: {
           role: 'textbox',

         },
       }
       ```

       - Arrow Left/Right to move between buttons
       - Home/End to jump to first/last button
       - Tab to leave toolbar and enter editor
    5. Add aria-label to Write/Preview tabs:
       ```typescript
       <div role="tablist" aria-label="Editor view">
       ```

<task name="performance-optimization">
  <description>Optimize editor performance for large content (10k+ words)</description>
  <steps>
    1. Add shouldRerenderOnTransaction: false to useEditor if not already set:
       ```typescript
       const editor = useEditor({
         ...config,
         shouldRerenderOnTransaction: false,
       });
       ```
       Note: This prevents React re-renders on every keystroke. The editor
       manages its own DOM updates.
    2. Debounce the onChange callback to reduce parent re-renders:
       ```typescript
       import { useRef, useCallback } from 'react';

       const debounceTimer = useRef<NodeJS.Timeout>();

       const debouncedOnChange = useCallback((html: string) => {
         clearTimeout(debounceTimer.current);
         debounceTimer.current = setTimeout(() => {
           onChange(html);
         }, 150); // 150ms debounce
       }, [onChange]);
       ```
    3. Memoize the EditorToolbar with React.memo:
       ```typescript
       export const EditorToolbar = React.memo(function EditorToolbar(...) {
         ...
       });
       ```
    4. Memoize EditorStatusBar with React.memo
    5. Ensure preview tab uses lazy update (only updates when tab is active):
       ```typescript
       const [previewHtml, setPreviewHtml] = useState('');
       // Only update preview HTML when switching to preview tab
       useEffect(() => {
         if (activeTab === 'preview' && editor) {
           setPreviewHtml(editor.getHTML());
         }
       }, [activeTab]);
       ```
    6. Test with large content (paste 10k+ words) and verify:
       - No visible input lag
       - Toolbar remains responsive
       - Modal scroll works smoothly
  </steps>
  <acceptance>
    - No input lag with 10k+ word documents
    - onChange debounced to 150ms
    - Toolbar and StatusBar memoized
    - Preview only updates when visible
    - React DevTools shows minimal re-renders during typing
  </acceptance>
</task>

<task name="edge-cases-and-error-handling">
  <description>Handle edge cases: empty content, malformed HTML, paste handling, modal lifecycle</description>
  <steps>
    1. Handle empty content initialization:
       - If content is empty string, show placeholder
       - If content is null/undefined, default to empty string
    2. Handle malformed HTML input:
       - TipTap's parser handles this gracefully (strips unknown tags)
       - Test with content containing script tags (should be stripped)
       - Test with unclosed tags (should auto-close)
    3. Handle paste events:
       - TipTap handles paste by default (strips unknown formatting)
       - Test pasting from Google Docs, Word, web pages
       - Verify pasted content is clean (no style attributes, no font tags)
    4. Handle modal open/close lifecycle:
       - When modal opens: initialize editor with content.body
       - When modal closes: editor is unmounted (cleanup happens via useEditor)
       - When modal re-opens with different content: editor re-initializes
       - Potential issue: useEditor content is set on mount only
       - Fix: Add useEffect to update editor content when formData.body changes
         from external source (i.e., when content prop changes):
         ```typescript
         // In RichTextEditor:
         useEffect(() => {
           if (editor && content !== editor.getHTML()) {
             // Only reset if content changed externally (not from user typing)
             // Use a ref to track user-initiated changes
           }
         }, [content]);
         ```
       - Simpler approach: key the RichTextEditor on content._id:
         ```typescript
         <RichTextEditor key={content?._id} content={formData.body} ... />
         ```
         This forces remount when switching between content items.
    5. Handle form submission with empty editor:
       - If editor is empty (only has <p></p>), treat as empty string
       - Validate minimum character count on plain text, not HTML
    6. Handle the case where user clears all content:
       - Editor should show placeholder
       - Status bar should show 0 chars, 0 words
       - "Min 50 chars" warning should appear
  </steps>
  <acceptance>
    - Empty content shows placeholder
    - Malformed HTML loads without errors
    - Pasted content is clean (no inline styles)
    - Modal re-opening with different content works correctly
    - Empty editor triggers validation (min chars warning)
    - Script tags in content are stripped
    - No console errors in any edge case
  </acceptance>
</task>
