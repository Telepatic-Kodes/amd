For each file in components/brand/ and app/(dashboard)/brand/page.tsx, replace hardcoded Tailwind color utilities with CSS variable equivalents. Use the strategy components as the reference pattern (read StrategyPerformancePanel.tsx for the established pattern).

**Migration mapping (apply consistently):**

Backgrounds:
- `bg-white` → `bg-[var(--card-bg)]`
- `bg-stone-50` → `bg-[var(--surface-0)]`
- `bg-stone-100` → `bg-[var(--surface-1)]`
- `bg-stone-200` → `bg-[var(--surface-2)]`
- `bg-stone-300` → `bg-[var(--surface-3)]`
- `bg-stone-900` → keep as-is if used for dark surfaces (e.g., sidebar); otherwise `bg-[var(--text-primary)]`
- `bg-orange-50` → `bg-[var(--accent-muted)]`
- `bg-orange-100` → `bg-[var(--accent-muted)]`
- `bg-orange-600` → `bg-[var(--accent)]`

Text:
- `text-stone-900` → `text-[var(--text-primary)]`
- `text-stone-800` → `text-[var(--text-primary)]`
- `text-stone-700` → `text-[var(--text-secondary)]`
- `text-stone-600` → `text-[var(--text-secondary)]`
- `text-stone-500` → `text-[var(--text-tertiary)]`
- `text-stone-400` → `text-[var(--text-tertiary)]`
- `text-stone-300` → `text-[var(--text-tertiary)]`
- `text-orange-600` → `text-[var(--accent)]`
- `text-orange-500` → `text-[var(--accent)]`
- `text-gray-*` → map to equivalent text-[var(--text-*)] based on shade

Borders:
- `border-stone-200` → `border-[var(--border)]`
- `border-stone-100` → `border-[var(--border)]`
- `border-stone-300` → `border-[var(--border-hover)]`
- `border-gray-200` → `border-[var(--border)]`
- `border-gray-300` → `border-[var(--border-hover)]`
- `border-orange-200` → `border-[var(--accent-muted)]`

Hover states:
- `hover:bg-stone-50` → `hover:bg-[var(--surface-1)]`
- `hover:bg-stone-100` → `hover:bg-[var(--surface-2)]`
- `hover:bg-orange-50` → `hover:bg-[var(--accent-muted)]`

Status/badge colors (use badge tokens from globals.css):
- `bg-blue-50` → `bg-[var(--badge-blue-bg)]`
- `text-blue-600` or `text-blue-700` → `text-[var(--badge-blue-text)]`
- `bg-green-50` → `bg-[var(--badge-green-bg)]`
- `text-green-600` or `text-green-700` → `text-[var(--badge-green-text)]`
- `bg-red-50` → `bg-[var(--badge-red-bg)]`
- `text-red-600` or `text-red-700` → `text-[var(--badge-red-text)]`
- `bg-amber-50` → `bg-[var(--badge-amber-bg)]`
- `text-amber-600` or `text-amber-700` → `text-[var(--badge-amber-text)]`
- `bg-purple-50` → `bg-[var(--badge-purple-bg)]`
- `text-purple-600` or `text-purple-700` → `text-[var(--badge-purple-text)]`

**IMPORTANT EXCEPTIONS:**
1. BrandManual.tsx uses `brand-manual-doc` class to force light theme for document view. Keep any classes inside brand-manual-doc sections AS-IS (they are overridden by CSS). Only migrate classes OUTSIDE the brand-manual-doc wrapper.
2. If a component has inline color logic like `theme === 'dark' ? 'bg-black' : 'bg-white'` — remove the conditional and use the CSS variable (it handles both themes).
3. Preserve any `text-white` on dark/accent backgrounds (these are genuinely white text on colored surfaces).
4. When a gradient uses stone colors (e.g., `from-stone-50 to-white`), convert to CSS variable: `from-[var(--surface-0)] to-[var(--card-bg)]`.

Work through each file systematically. Read each file, apply the mapping, write the updated file.
