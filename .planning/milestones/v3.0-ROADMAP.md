# Milestone v3.0: Intelligence & Scale

**Status:** SHIPPED 2026-02-07
**Phases:** 13-18
**Total Plans:** 20

## Overview

Transform AMD from a single-user publishing tool into a multi-user, multi-platform marketing intelligence system with real analytics data.

**Target Features:**
- Analytics & Intelligence (internal metrics dashboards + LinkedIn API real engagement data)
- Multi-Platform Publishing (expand from LinkedIn to Twitter/X, Instagram; cross-platform scheduling)
- Team Collaboration (real multi-user auth with Clerk, separate accounts, roles & permissions)
- Content version history and automated performance reports

**Priority Order:** Authentication first -> Analytics/Multi-Platform (parallel) -> Collaboration -> Reports

## Phases

### Phase 13: Multi-User Authentication Foundation

**Goal:** Users can securely access the system with separate accounts and data isolation, establishing the foundation for all team features

**Depends on:** Phase 12 (v2.0 complete)

**Requirements:** AUTH-01, AUTH-02, AUTH-03, AUTH-04, UX-01, UX-02, UX-03, UX-04

**Success Criteria:**
1. User can create account and log in with email/password through Clerk
2. User can see only their own content and data (no leakage across users)
3. Existing v2.0 data is assigned to a "system owner" account (no orphaned records)
4. All pages require authentication (redirect to login if not authenticated)
5. User session persists across browser tabs and page refreshes

**Plans:** 4 plans in 3 waves

- [x] 13-01: Clerk + Convex auth infrastructure, middleware, sign-in/sign-up pages (Wave 1)
- [x] 13-02: Schema (users table, userId fields), auth helpers, migration mutation (Wave 2)
- [x] 13-02b: Auth enforcement on all queries/mutations (Wave 2)
- [x] 13-03: Dashboard auth UI, user sync, migration prompt, toasts (Wave 3)

## Milestone Summary

**Key Decisions:**
- Clerk chosen over Convex Auth (production-ready, free tier 10K MAU, official Convex integration)
- Direct platform SDKs (twitter-api-v2, facebook-nodejs-business-sdk) over wrappers
- In-memory analytics aggregation (no @convex-dev/aggregate dependency)
- Dynamic TTL caching for LinkedIn engagement (hot/warm/cold post tiers)
- Client-side CSV generation (Blob + download link, avoids backend endpoint)
- Twitter PKCE flow for secure OAuth 2.0
- Instagram via Facebook OAuth with Page linking requirement
- Pure TypeScript shared adapter (no Convex imports, importable by both backend/frontend)
- Promise.allSettled for batch publish (one platform failure doesn't block others)
- 6-role RBAC hierarchy (owner > admin > editor > reviewer > publisher > viewer)
- Sequential version numbering (1, 2, 3...) for simplicity
- Client-side text diffing for performance
- Runtime split for Node.js dependencies (reports.ts V8 + reportsActions.ts Node.js)
- Dark theme email templates matching dashboard UI
- AI narrative as optional (user setting, default: true)

**Issues Resolved:**
- TypeScript strict compilation maintained throughout all 20 plans
- Convex deploys clean after every plan
- Backward compatibility maintained during auth migration (optional userId fields)
- Cross-platform adapter designed as pure TS to work in both environments

**Issues Deferred:**
- Instagram App Review (60-90 day approval timeline)
- Twitter Analytics (requires Basic tier at $200/mo)
- Pre-existing TypeScript error in convex/topicSuggestions.ts:189

**Technical Debt Incurred:**
- Some traceability table entries in REQUIREMENTS.md still show "Pending" despite being complete
- v2.0 milestone was never formally archived
