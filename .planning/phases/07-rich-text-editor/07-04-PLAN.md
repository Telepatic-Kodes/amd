# Plan 07-04: Polish, Accessibility & Edge Cases

**Objective:** Add accessibility features, optimize performance for large documents, handle edge cases, improve mobile experience.

**Effort:** 3-4 hours
**Risk:** Low

## Tasks

### Task 1: Accessibility Improvements

**Description:** Add ARIA labels and improve keyboard navigation.

**Steps:**
1. Add `aria-label` to all toolbar buttons
2. Add `aria-active` or `aria-pressed` to toggle buttons
3. Add `role="toolbar"` to EditorToolbar
4. Add `role="tablist"` to tab container
5. Ensure all buttons are keyboard accessible (Tab key navigation)
6. Test with screen reader (NVDA or JAWS simulation)
7. Verify focus indicators visible on all buttons

**Acceptance:**
- [ ] All buttons have aria-labels
- [ ] Keyboard navigation works (Tab moves through buttons)
- [ ] Focus indicators clearly visible
- [ ] Screen reader announces button purposes
- [ ] Tab ordering logical

---

### Task 2: Performance Optimization

**Description:** Optimize for large documents (10k+ words).

**Steps:**
1. Implement `shouldRerenderOnTransaction: false` (already in Plan 07-01, verify)
2. Memoize EditorToolbar component with `React.memo`
3. Memoize EditorStatusBar component with `React.memo`
4. Add 150ms debounce to onChange callback (prevent excessive updates)
5. Test with 10,000+ word document
6. Measure typing latency (should feel instant)
7. Profile with React DevTools to check render counts

**Acceptance:**
- [ ] No lag on typing in large documents
- [ ] Status bar doesn't cause excessive re-renders
- [ ] Memory usage reasonable
- [ ] onChange batched appropriately

---

### Task 3: Edge Case Handling

**Description:** Handle various edge cases and error conditions.

**Steps:**
1. Handle empty content gracefully (show placeholder)
2. Handle content > 100k characters (warn user, allow anyway)
3. Handle pasted content with invalid formatting (clean automatically)
4. Handle images in pasted content (strip or warn)
5. Handle very long single words (no line break, manage overflow)
6. Handle special characters and unicode (test with emoji, special characters)
7. Test undo/redo extensively (should never corrupt data)

**Acceptance:**
- [ ] Empty editor shows placeholder
- [ ] No crashes with unusual content
- [ ] Paste from Word cleans formatting properly
- [ ] Undo/redo reliable
- [ ] Unicode and emoji handled

---

### Task 4: Mobile Touch Optimization

**Description:** Improve experience on touch devices.

**Steps:**
1. Ensure button touch targets 44x44px (already in Plan 07-02, verify)
2. Hide advanced toolbar options on mobile (<640px)
3. Keep essential buttons: Bold, Italic, Lists, Link, Undo/Redo
4. Test BubbleMenu on mobile (verify doesn't cover selection)
5. Test LinkDialog on mobile (sufficient space for input)
6. Handle virtual keyboard (ensure editor doesn't scroll away)
7. Test with actual mobile device or Chrome DevTools mobile emulation

**Acceptance:**
- [ ] Touch targets properly sized
- [ ] No horizontal scroll needed
- [ ] Toolbar usable with fingers (not cramped)
- [ ] Virtual keyboard doesn't cover input
- [ ] Smooth scrolling with content
