The hash utility implements composite key generation for deduplication (SYNC-02).

**Why composite key instead of just GUID:**
- Many feeds have unreliable/duplicate GUIDs
- Some feeds don't include GUID at all
- Different feeds may reuse same GUID
- Composite key is more reliable for true deduplication

**Composite key formula:**
`SHA-256(feedUrl + "|" + (guid || link) + "|" + pubDate + "|" + title)`

Implementation requirements:

1. Export async function `generateContentHash(params: {...}): Promise<string>`
   - Parameters: `{ feedUrl: string, guid?: string, link: string, pubDate?: string, title: string }`
   - Uses Web Crypto API (available in Convex runtime)
   - Returns lowercase hex string (64 chars)

2. Handle missing optional fields:
   - If guid is missing, use link as primary identifier
   - If pubDate is missing, use empty string (still unique via title+link)
   - Normalize all inputs: trim whitespace, lowercase URLs

3. Use Web Crypto API (NOT Node's crypto module - Convex is edge runtime):
```typescript
async function sha256(message: string): Promise<string> {
  const msgBuffer = new TextEncoder().encode(message);
  const hashBuffer = await crypto.subtle.digest('SHA-256', msgBuffer);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}
```

4. Add JSDoc comments explaining the composite key strategy.

Include TypeScript types for parameters.

Create validation utility at `convex/feeds/utils/validation.ts`.

This implements lenient validation (SYNC-03) and normalization (SYNC-07).

**Validation rules (lenient - don't reject, warn and fix):**

1. `validateFeedItem(item: RawFeedItem): ValidationResult`
   - Returns: `{ valid: boolean, errors: string[], warnings: string[], item: RawFeedItem }`
   - Required: must have (title OR description) AND (link OR guid)
   - If missing required fields, valid=false with specific error messages
   - If optional fields missing/malformed, valid=true with warnings

2. `normalizeFeedItem(item: RawFeedItem, feedUrl: string): NormalizedFeedItem`
   - Normalize title: trim, decode HTML entities, max 500 chars
   - Normalize link: absolute URL (resolve relative against feedUrl), trim
   - Normalize content: trim, decode HTML entities, preserve HTML structure
   - Normalize publishedAt: parse various date formats to Unix timestamp (number)
     - Handle: ISO 8601, RFC 2822, RFC 822, common variations
     - If unparseable, use null (not current date - that causes false updates)
   - Normalize categories: array of trimmed strings, deduplicated
   - Normalize author: trim, max 200 chars

3. Date parsing helper (internal):
   - Try `Date.parse()` first (handles ISO and RFC)
   - If NaN, try common patterns
   - Return null if all fail (better than guessing)

4. HTML entity decoder (internal):
   - Decode: &amp; &lt; &gt; &quot; &#39; &apos;
   - Don't use external library - simple regex replacement

**Type definitions:**

```typescript
interface RawFeedItem {
  title?: string;
  description?: string;
  link?: string;
  guid?: string;
  pubDate?: string;
  published?: string;  // Atom format
  author?: string;
  creator?: string;    // Dublin Core
  categories?: string[];
  content?: string;
  "content:encoded"?: string;  // Common RSS extension
}

interface NormalizedFeedItem {
  title: string;
  link: string;
  guid: string | null;
  content: string | null;
  summary: string | null;
  author: string | null;
  publishedAt: number | null;
  categories: string[];
}

interface ValidationResult {
  valid: boolean;
  errors: string[];
  warnings: string[];
  item: RawFeedItem;
}
```
