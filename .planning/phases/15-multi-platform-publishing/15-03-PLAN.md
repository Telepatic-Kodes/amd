**convex/instagram/mutations.ts** — Following LinkedIn mutations pattern:

1. `storeConnection` (internalMutation): Stores Instagram connection. Args: instagramUserId, username, displayName, profilePictureUrl, facebookPageId, facebookPageName, accessToken, accessTokenExpiresAt, scopes. Upserts by instagramUserId. Logs to auditLog.
2. `disconnect` (mutation): Sets status to "disconnected". Args: { connectionId: v.id("instagramConnections") }. Logs to auditLog.
3. `logPublishAttempt` (internalMutation): Creates pending instagramPublishLog entry. Args: { contentId, connectionId, mediaType }.
4. `updatePublishLog` (internalMutation): Updates log with result. Args: { logId, status, instagramMediaId, errorMessage, metadata }.
5. `incrementDailyCount` (internalMutation): Increments dailyPostCount. Resets if new day.
6. `markExpired` (internalMutation): Marks connection as expired.

**convex/instagram/queries.ts** — Following LinkedIn queries pattern:

1. `getConnection` (query): Returns active Instagram connection without token. Includes facebookPageName, facebookPageId for UI display. Calculates expiresInDays (Instagram tokens expire 60 days). Sets isExpiringSoon if < 7 days.
2. `getConnectionStatus` (query): Lightweight status. Returns { isConnected, status, username, displayName, profilePictureUrl, facebookPageName, dailyPostCount }.
3. `getPublishHistory` (query): Publish logs for a content ID. Ordered desc.
4. `getRecentPublishLogs` (query): Recent publish logs. Default limit 20.

**convex/instagram/actions.ts** — Instagram Graph API integration:

1. `exchangeCodeForTokens` (internalAction):
   - Args: { code: v.string(), redirectUri: v.string() }
   - Step 1: Exchange code for short-lived token: GET https://graph.facebook.com/v19.0/oauth/access_token?client_id={}&client_secret={}&redirect_uri={}&code={}
   - Step 2: Exchange for long-lived token: GET https://graph.facebook.com/v19.0/oauth/access_token?grant_type=fb_exchange_token&client_id={}&client_secret={}&fb_exchange_token={short_lived_token}
   - Step 3: Get user's Facebook Pages: GET https://graph.facebook.com/v19.0/me/accounts?access_token={long_lived_token}
   - Step 4: For each page, check for linked Instagram Business account: GET https://graph.facebook.com/v19.0/{page_id}?fields=instagram_business_account&access_token={page_access_token}
   - Step 5: Get Instagram profile: GET https://graph.facebook.com/v19.0/{ig_user_id}?fields=id,username,name,profile_picture_url&access_token={}
   - Step 6: Store connection with page ID, IG user ID, long-lived token (expires_in from step 2, typically 60 days)
   - If no Instagram Business account found, throw error: "No se encontro cuenta de Instagram Business vinculada a tus paginas de Facebook. Necesitas una cuenta de Instagram Business conectada a una Pagina de Facebook."
   - Return { username, displayName }

2. `publishToInstagram` (action):
   - Args: { contentId: v.id("content"), imageUrl: v.string(), imageUrls: v.optional(v.array(v.string())) }
   - Get content, validate status approved/scheduled
   - Get connection, validate connected
   - Validate caption using validateCaption()
   - Caption text = content.body (truncated to 2200 chars)
   - If imageUrls provided and length >= 2: CAROUSEL flow
   - If single imageUrl: SINGLE IMAGE flow

   **Single image flow (IG-02):**
   - Step 1: Create media container: POST https://graph.facebook.com/v19.0/{ig_user_id}/media with { image_url, caption, access_token }
   - Step 2: Publish: POST https://graph.facebook.com/v19.0/{ig_user_id}/media_publish with { creation_id, access_token }
   - Log result, increment daily count

   **Carousel flow (IG-03):**
   - Step 1: Create item containers for each image: POST https://graph.facebook.com/v19.0/{ig_user_id}/media with { image_url, is_carousel_item: true, access_token }
   - Step 2: Create carousel container: POST https://graph.facebook.com/v19.0/{ig_user_id}/media with { media_type: "CAROUSEL", children: [container_ids], caption, access_token }
   - Step 3: Publish carousel: POST https://graph.facebook.com/v19.0/{ig_user_id}/media_publish with { creation_id, access_token }
   - Log result with imageCount metadata

   Handle 429 rate limit with Spanish message. Handle API errors with clear messages.
   Update content status to "published" on success.
   Return { success, instagramMediaId, permalink }

IMPORTANT: Instagram Container API is async. After creating a container, you may need to poll GET https://graph.facebook.com/v19.0/{container_id}?fields=status_code until status_code is "FINISHED" before publishing. Add a simple retry with 2-second delay, max 5 attempts.

IMPORTANT: The access_token used for Instagram API calls should be the PAGE access token if available, or the long-lived user token. For simplicity in this phase, use the long-lived user token stored in the connection.
