**convex/twitter/threadSplitter.ts** — Pure utility function (no Convex, just logic):

Create `splitIntoThread(text: string, maxLength?: number): string[]` function:
- Default maxLength = 280 (Twitter's limit)
- If text fits in one tweet (<=280 chars), return [text]
- For threads, add thread indicators: "(1/N)" at the end of each tweet
- Account for the indicator length when splitting (e.g., " (1/3)" = 6 chars, so content gets 274 chars)
- Split on paragraph breaks first (\n\n), then sentence breaks (. or ! or ?), then word boundaries (space)
- Never break mid-word
- Never leave a tweet with only whitespace
- If a single word exceeds maxLength, truncate it with "..."
- Export type `ThreadResult = { tweets: string[]; isThread: boolean; totalChars: number }`
- Export function `splitIntoThread(text: string, maxLength?: number): ThreadResult`

3. `getActiveConnections` — Returns all connected (non-expired) Twitter connections. No args. Used by cron jobs.

All internal queries use `internalQuery` from "../_generated/server".

**convex/twitter/mutations.ts** — Following LinkedIn mutations pattern:

1. `storeConnection` (internalMutation): Stores Twitter connection after OAuth. Args match twitterConnections schema fields. Checks for existing connection by twitterUserId, updates if exists, creates if new. Logs to auditLog.
2. `disconnect` (mutation): Sets connection status to "disconnected". Args: { connectionId: v.id("twitterConnections") }. Logs to auditLog.
3. `logPublishAttempt` (internalMutation): Creates pending entry in twitterPublishLog. Args: { contentId, connectionId }.
4. `updatePublishLog` (internalMutation): Updates publish log with result. Args: { logId, status, tweetIds, errorMessage, metadata }.
5. `incrementDailyCount` (internalMutation): Increments dailyTweetCount on connection. Resets count if lastTweetCountResetAt is from a previous day.
6. `markExpired` (internalMutation): Marks connection as expired. Args: { connectionId }.

**convex/twitter/queries.ts** — Following LinkedIn queries pattern:

1. `getConnection` (query): Returns active Twitter connection without tokens. Checks expiration, calculates expiresInDays, isExpiringSoon. Returns null if no connection.
2. `getConnectionStatus` (query): Lightweight status for dashboard widgets. Returns { isConnected, status, username, displayName, profileImageUrl, dailyTweetCount }.
3. `getPublishHistory` (query): Returns publish logs for a content ID. Args: { contentId: v.id("content") }. Ordered desc.
4. `getRecentPublishLogs` (query): Returns recent publish logs. Args: { limit: v.optional(v.number()) }. Default 20.

**convex/twitter/actions.ts** — Following LinkedIn actions pattern:

1. `exchangeCodeForTokens` (internalAction):
   - Args: { code: v.string(), redirectUri: v.string(), codeVerifier: v.string() }
   - POST to https://api.twitter.com/2/oauth2/token with: grant_type=authorization_code, code, redirect_uri, client_id, code_verifier
   - Use Basic Auth header (base64 of CLIENT_ID:CLIENT_SECRET) for confidential client
   - Parse response for access_token, refresh_token, expires_in
   - GET https://api.twitter.com/2/users/me?user.fields=profile_image_url to get user info
   - Call internal.twitter.mutations.storeConnection with all data
   - Return { username, displayName }

2. `publishToTwitter` (action):
   - Args: { contentId: v.id("content") }
   - Get content via internal query, validate status is "approved" or "scheduled"
   - Get connection via public query, validate connected and not rate-limited
   - Get full connection with token via internal query
   - Use threadSplitter to determine if thread or single tweet
   - For single tweet: POST https://api.twitter.com/2/tweets with { text }
   - For thread: POST first tweet, then each subsequent tweet with { text, reply: { in_reply_to_tweet_id } } chaining IDs
   - Log pending attempt, then update with result
   - Increment daily count on success
   - Update content status to "published" and set publishedUrl
   - Return { success, tweetIds, tweetUrl }

IMPORTANT: Twitter API v2 uses Bearer token auth (Authorization: Bearer {accessToken}).
IMPORTANT: Rate limit for tweets is 200 per 15 min window for app, but we enforce a conservative daily limit (default 50/day, configurable).
IMPORTANT: Handle 429 (rate limited) responses gracefully with clear Spanish error message.
