```typescript
/**
 * Get the frontend URL from environment, with fallback to localhost for dev.
 * In production, FRONTEND_URL must be set in Convex Dashboard.
 */
export function getFrontendUrl(): string {
  const url = process.env.FRONTEND_URL;
  if (!url) {
    console.warn("FRONTEND_URL not set, defaulting to http://localhost:3000");
    return "http://localhost:3000";
  }
  return url.replace(/\/$/, ""); // Remove trailing slash
}

/**
 * Build a Convex HTTP callback URL from the request origin.
 * Uses the Convex .site domain as the callback target.
 */
export function getOAuthCallbackUrl(requestUrl: string, path: string): string {
  const url = new URL(requestUrl);
  return `${url.origin}${path}`;
}
```

2. Update `convex/http.ts` to use the helper instead of inline `process.env.FRONTEND_URL || "http://localhost:3000"`:
- Import `getFrontendUrl` from `./oauthHelpers`
- Replace ALL 6 occurrences of `const frontendUrl = process.env.FRONTEND_URL || "http://localhost:3000"` with `const frontendUrl = getFrontendUrl()`
- This is a pure refactor -- no behavior changes, just DRY-ing the pattern
- IMPORTANT: Do NOT change the callback URL logic that uses `request.url` origin for the Convex .site domain -- that's correct and must stay

3. Verify the refactor doesn't break anything:
- The OAuth callbacks still use the Convex .site domain (derived from request URL)
- The frontend redirect still uses FRONTEND_URL (now via helper)
- Both LinkedIn, Twitter, and Instagram flows maintain their current structure

CRITICAL: The OAuth callback URL (where the provider redirects back to) is the Convex HTTP endpoint (.site domain). The FRONTEND_URL is where the user gets redirected after Convex processes the callback. These are DIFFERENT URLs and must not be confused.
