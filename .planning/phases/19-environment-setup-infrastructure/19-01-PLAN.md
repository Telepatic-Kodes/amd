Include comments explaining which are set in Vercel vs Convex Dashboard vs .env.local.

2. Create `ai-marketing-department/ai-marketing-department/lib/validateEnv.ts`:
- Export a `validateEnvironment()` function
- In production (detected via `process.env.NODE_ENV === 'production'` OR `process.env.VERCEL_ENV === 'production'`):
  - Throw if `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` starts with `pk_test_`
  - Throw if `NEXT_PUBLIC_CONVEX_URL` contains `localhost` or is undefined
  - Log warning if `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` is undefined
- In all environments:
  - Throw if `NEXT_PUBLIC_CONVEX_URL` is undefined (app can't work without it)
- Function should log "Environment validation passed" on success
- IMPORTANT: This runs at build time and server startup, NOT on client. Use `typeof window === 'undefined'` guard.

3. Import and call `validateEnvironment()` in the root `layout.tsx` server component (it's a server component so this runs server-side only). Add it at the top of the file body, before the return. If layout.tsx already has imports, add after existing imports.

PITFALL: Do NOT use `process.env.VERCEL` to detect Vercel -- it's always set in preview too. Use `VERCEL_ENV === 'production'` specifically for production checks.
