1. Create components/content/VersionHistory.tsx:
   - Props: { contentId: Id<"content">, onCompare?: (vA: Id, vB: Id) => void }
   - Uses `useQuery(api.contentVersions.listContentVersions, { contentId })` to get versions
   - Layout: Vertical timeline (like a git log):
     - Each entry: version number, changeType icon (pencil for edit, arrow for status change, undo for rollback, plus for created), changeSummary text, editedByName, relative time (e.g., "hace 5 min")
     - Use Lucide icons: Pencil (edited), ArrowRight (status_change), RotateCcw (rollback), Plus (created)
   - Selection: User can click two versions to select them for comparison. Selected versions get highlighted border.
   - "Comparar" button appears when exactly 2 versions selected → calls onCompare(versionAId, versionBId)
   - "Revertir" button on each version (except current/latest) → opens RollbackDialog
   - Empty state: "Sin historial de versiones" if no versions
   - Loading state: Skeleton timeline entries
   - Mobile: Full width, compact layout. Touch-friendly tap targets (min 44px).
   - Relative time formatting: Use Intl.RelativeTimeFormat('es') or manual Spanish strings (hace X minutos/horas/días)

2. Create components/content/VersionDiff.tsx:
   - Props: { versionAId: Id<"contentVersions">, versionBId: Id<"contentVersions">, onClose: () => void }
   - Uses `useQuery(api.contentVersions.getVersionDiff, { versionAId, versionBId })` to get diff data
   - Layout: Modal or slide-over panel with two columns (side by side on desktop, stacked on mobile):
     - Header: "Versión {A} vs Versión {B}" with close button
     - For each field that changed (titleChanged, bodyChanged, summaryChanged, statusChanged):
       - Show field label in Spanish
       - Show Version A value on left, Version B value on right
       - Highlight changed fields with amber/yellow background
       - For body text: Show full text of each version (client-side text diff is complex and not worth the dependency — simple side-by-side comparison is sufficient for MVP)
     - If no fields changed: show "Las versiones son idénticas"
   - Style: Dark theme consistent with existing UI (bg-[var(--surface)], border-[var(--border)], text-[var(--text-primary)])
   - Mobile: Stack columns vertically, scrollable

3. Create components/content/RollbackDialog.tsx:
   - Props: { contentId: Id<"content">, versionId: Id<"contentVersions">, versionNumber: number, onClose: () => void, onSuccess: () => void }
   - Confirmation dialog (not a full page):
     - Title: "Revertir a versión {N}"
     - Body: "Esta acción restaurará el contenido a la versión {N}. Se creará una nueva entrada en el historial. ¿Deseas continuar?"
     - Two buttons: "Cancelar" (secondary) and "Revertir" (destructive/amber)
   - Uses `useMutation(api.contentVersions.rollbackToVersion)` on confirm
   - On success: toast "Contenido revertido a versión {N}", call onSuccess(), call onClose()
   - On error: toast with error message
   - Loading state on Revertir button while mutation runs

4. In content/page.tsx, integrate version history:

     - Section title: "Historial de versiones" with History icon
     - Render VersionHistory component with selected contentId
   - When user clicks "Comparar": show VersionDiff as a modal/overlay
   - When user clicks "Revertir": show RollbackDialog
   - State management: useState for selectedVersions, showDiff boolean, rollbackTarget
   - The version history section should be collapsible (default collapsed to not overwhelm the detail panel) — use a disclosure/accordion pattern consistent with existing accordions in the codebase
   - Add appropriate imports

Note on existing content page structure: The content page has a left-side list and right-side detail panel. The version history goes in the detail panel, below existing sections. Read the current page.tsx to understand the layout before adding components.
