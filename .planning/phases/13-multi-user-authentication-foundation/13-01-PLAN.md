    2. Create `convex/auth.config.ts` for Convex to validate Clerk JWTs:
       ```typescript
       import { AuthConfig } from "convex/server";

       export default {
         providers: [
           {
             domain: process.env.CLERK_JWT_ISSUER_DOMAIN!,
             applicationID: "convex",
           },
         ],
       } satisfies AuthConfig;
       ```

    3. Update `app/layout.tsx` to wrap with ClerkProvider:
       - Import `ClerkProvider` from `@clerk/nextjs`
       - Wrap the `<body>` content with `<ClerkProvider>` OUTSIDE of ConvexClientProvider

       - Keep the existing font setup, metadata, and dark theme
       - Set `lang="es"` on the html tag (Spanish-first)

    4. Update `app/ConvexClientProvider.tsx`:
       - Replace `ConvexProvider` with `ConvexProviderWithClerk` from `"convex/react-clerk"`
       - Import `useAuth` from `@clerk/nextjs`
       - Pass `useAuth={useAuth}` prop to `ConvexProviderWithClerk`
       - Keep the existing `ToastProvider` wrapper inside
       - The ConvexReactClient initialization stays the same

    5. Create `middleware.ts` in the frontend root (`ai-marketing-department/ai-marketing-department/middleware.ts`):
       - Import `clerkMiddleware` and `createRouteMatcher` from `@clerk/nextjs/server`
       - Define public routes: `/sign-in(.*)`, `/sign-up(.*)`, `/api/clerk(.*)` (for future webhooks)
       - For ALL non-public routes, call `await auth.protect()` which redirects to sign-in
       - Use standard matcher config that skips Next.js internals and static files
       - IMPORTANT: This is first-line defense only. Real auth enforcement happens in Convex functions (Plan 02).

    - `NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up`
    - `NEXT_PUBLIC_CLERK_AFTER_SIGN_IN_URL=/`
    - `NEXT_PUBLIC_CLERK_AFTER_SIGN_UP_URL=/onboarding`
    - `CLERK_JWT_ISSUER_DOMAIN` in Convex dashboard environment variables
