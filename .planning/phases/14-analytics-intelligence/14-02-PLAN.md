  <name>Task 1: Create LinkedIn engagement fetcher action with rate-limit-aware caching</name>
  <files>convex/linkedin/engagement.ts, convex/linkedin/internalQueries.ts</files>
  <action>
Create `convex/linkedin/engagement.ts` with two exported functions:

**1. `fetchPostEngagement` (internalAction)**
Args: `{ contentId: v.id("content"), linkedinPostUrn: v.string(), connectionId: v.id("linkedinConnections") }`

Logic:
- Get the full connection with token via `internal.linkedin.internalQueries.getConnectionWithToken`
- If no token or connection expired, skip silently (log but don't throw -- this runs in a cron)
- Call LinkedIn API endpoint: `GET https://api.linkedin.com/rest/socialMetadata/{postUrn}` with headers:
  - `Authorization: Bearer {accessToken}`
  - `Linkedin-Version: 202601`
  - `X-Restli-Protocol-Version: 2.0.0`
- If the endpoint returns engagement data, extract: likes (from reactionSummaries), comments (commentSummary.count), shares (shareSummary.count)
- NOTE: LinkedIn's Community Management API v2 uses different endpoints. The simpler approach is `GET https://api.linkedin.com/rest/posts/{postUrn}` which returns basic stats. If the exact endpoint shape isn't available, use the UGC post stats endpoint: `GET https://api.linkedin.com/v2/socialActions/{postUrn}` -- handle both patterns with a try/fallback.
- For impressions, try `GET https://api.linkedin.com/v2/organizationalEntityShareStatistics` if available, otherwise store impressions as 0 (many personal LinkedIn accounts don't have access to impression data)
- Store the snapshot using a mutation that inserts into `linkedinEngagement`:
  ```
  { contentId, linkedinPostUrn, likes, comments, shares, impressions, clicks: 0, engagement_rate, fetchedAt: Date.now(), userId }
  ```
- engagement_rate = (likes + comments + shares) / max(impressions, 1) * 100

**2. `fetchAllRecentEngagement` (action -- public, called by cron)**
Args: none

Logic:
- Get active LinkedIn connection via `api.linkedin.queries.getConnection`
- If no connection or expired, return early
- Query `linkedinPublishLog` for posts with status "published" (use an internal query)
- Apply dynamic TTL to decide which posts need refreshing:
  - Hot (published < 48 hours ago): fetch if last snapshot > 30 min ago
  - Warm (published 2-14 days ago): fetch if last snapshot > 4 hours ago
  - Cold (published > 14 days ago): fetch if last snapshot > 24 hours ago
- For each post that needs refresh, check the last `linkedinEngagement` snapshot fetchedAt
- Call `fetchPostEngagement` for each eligible post (up to 10 per run to stay under rate limits -- LinkedIn ~500 calls/day)
- Return summary: { fetched: number, skipped: number, errors: number }

Also add to `convex/linkedin/internalQueries.ts`:
- `getPublishedPostsWithUrn` (internalQuery): fetches linkedinPublishLog entries with status "published" that have a linkedinPostUrn, joined with content table to get publishedAt timestamp. Returns array of { contentId, linkedinPostUrn, publishedAt, connectionId }.
- `getLatestEngagementSnapshot` (internalQuery): args { contentId }, queries linkedinEngagement by_contentId_fetchedAt desc, takes 1, returns the latest snapshot or null.

Create a helper internal mutation `storeEngagementSnapshot` in the same file or in `convex/linkedin/mutations.ts` that inserts into `linkedinEngagement`.

Handle errors gracefully: if LinkedIn API returns 401, log and mark connection expired via existing `markExpired` mutation. If 429 (rate limited), stop fetching remaining posts and return. All other errors: log and continue to next post.
